# Alibaba Cloud Connector — идеальный первый запуск

Источник: `Docs/session-notes/ONBOARDING_FIRST_LAUNCH_STANDARD.md`.
Целевой пользователь: enterprise/IT-специалист с операциями в Азии,
управляющий инфраструктурой на Alibaba Cloud параллельно с (или вместо)
AWS/Azure/GCP.

## 1. Credential type

BYOK, средний-высокий риск: AccessKey ID + AccessKey Secret (создаются
в RAM console), опционально предпочитаемый Region ID по умолчанию.
Пятая и последняя auth-модель из пяти гиперскейлеров — RPC-style
подпись запроса (HMAC-SHA1), не идентичная ни AWS SigV4, ни Azure/GCP
OAuth, ни OCI RSA-подписи.

## 2. Идеальный флоу

1. **Первое открытие** — `Empty` с прямой ссылкой на RAM console
   (создание AccessKey пары) + явная рекомендация ПЕРЕД созданием
   ключа: "создайте RAM-пользователя с политикой только для чтения
   (ReadOnlyAccess) для первого подключения — этого достаточно, чтобы
   увидеть свою инфраструктуру безопасно; права на управление
   инстансами понадобятся только если вы попросите меня
   запустить/остановить ECS-инстанс".
2. **Форма** — AccessKey ID + AccessKey Secret (password-type) +
   опциональный Region ID по умолчанию (например `cn-hangzhou`),
   явно помеченный "необязательно, но рекомендуется — большинство
   операций требуют региона".
3. **Диагностика при подключении** — лёгкий read-only вызов
   (`DescribeRegions` — не требует конкретного региона) сразу после
   сохранения ключей, чтобы подтвердить что подпись считается
   правильно И что ключи реально работают, прежде чем сохранять.
   Частая ошибка на этом шаге — неверная подпись из-за неправильного
   URL-encode (`+`/`*`/`~`) — если сигнатура не совпадает, вернуть
   человеку понятную формулировку "не удалось подтвердить ключи",
   не сырую ошибку подписи.
4. **После успеха** — сводка "облачного здоровья" по образцу
   AWS/Azure/GCP/OCI/DigitalOcean Connector: ECS running/stopped,
   OSS buckets, RDS instances, ACK clusters, баланс счёта.
5. **Ошибка невалидной подписи (`InvalidAccessKeyId.NotFound` /
   `SignatureDoesNotMatch`)** — по строке, не по коду: "не удалось
   подтвердить эти ключи в Alibaba Cloud — проверьте, что AccessKey ID
   и Secret скопированы полностью, без пробелов".
6. **Экспорт-контрольные/санкционные ограничения** — если Alibaba Cloud
   API вернёт отказ по географическому признаку (нетипичная, но
   возможная ошибка для некоторых юрисдикций), показать её как
   отдельный класс ошибки, не как "неверные ключи" — пользователь
   должен понять, что дело не в опечатке.

## 3. Что видно сразу после подключения

Cloud Overview (Ярус 3) — тот же паттерн, что и у AWS/Azure/GCP/OCI/
DigitalOcean: одна read-only функция, агрегирующая несколько API
вызовов в одну человеко-читаемую сводку, без необходимости лезть в
консоль Alibaba Cloud за первым впечатлением "всё ли в порядке".

## 4. Чего НЕТ в этом приложении (осознанно)

App Platform-аналоги (Serverless App Engine), AI/GenAI платформа
(PAI), и специфичные для Китая продукты (WeChat-интеграции и т.п.) —
вне скоупа v1, по прецеденту AWS/Azure/GCP/OCI Connector (операционное
ядро: compute/storage/managed-db/k8s-read/monitoring/billing).
